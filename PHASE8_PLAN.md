# Phase 8 — Visual bookshelves and chapter-by-chapter reading

Status: **approved and locally implemented**. Phase 7's live reindex succeeded. Docker/PostgreSQL/live MinIO and guest-access smoke testing remain for the deployment host.

## What you asked for / decisions confirmed

- Make books inviting to read in a **proper visual Markdown reader**, rather than reading their PDFs.
- Two shelves: an owner's **private shelf** and a **public shelf** anyone can browse and read without logging in.
- Source books from **both** completed PDF conversions and separately uploaded Markdown books.
- For signed-in readers, remember the **last-opened chapter** and let them explicitly mark individual chapters complete; a Continue Reading action resumes there (or advances to the next incomplete chapter). Do not claim to remember an exact paragraph/scroll position in this phase.
- Guests can read public books but have **no saved progress**. Signed-in readers can save **their own** progress on public books, including books published by another owner. No reader can view another reader's progress.

## Recommended product flow

1. **Add to shelf.** The owner selects a finished converted job and chooses **Add to my shelf**, or imports a Markdown book. A shelf book is a private, independently stored snapshot: ordered chapter Markdown, referenced supported image assets, title, optional author/description and an attractive generated cover treatment. The original PDF, ZIP, job ID, quality flags, review metadata, and private source-page viewer are **never published** by this action. Imported books never go through PDF conversion, OCR or AI. Adding an existing conversion does not change its ZIP or Phase 7 private search index.
2. **Import format (proposed default).** A single UTF-8 `.md` file is a one-chapter book. For multiple chapters and images, upload one `.zip` containing `book.json` (title, optional author/description, ordered chapter entries with display titles and relative `.md` filenames), those UTF-8 Markdown files and optional raster images under `assets/`. Provide a downloadable sample/template in the UI. Preserve the declared order; reject duplicate or missing chapters rather than guessing from filenames. Imported books start **private**. Limit compressed/uncompressed bytes, files, chapter count and Markdown size; reject encrypted/nested archives, duplicate names, symlinks, traversal, absolute paths, unexpected extensions, invalid UTF-8, SVG/HTML files and unsafe links. Accept only safe book-local image references; no remote images or embedded iframes. Error messages explain how to repair an import without exposing content in logs.
3. **Private shelf.** The owner sees their own shelf books (converted snapshots and imports) and can open a book, resume, change book metadata, or explicitly publish/unpublish it. Administrators may inspect under their existing role, but must **not publish another owner's book on their behalf**. A book is never public by default.
4. **Publish/unpublish.** A deliberate confirmation shows exactly what becomes public: title, description, chapter text and included images. Public listing and reader endpoints return only an owner's explicitly `PUBLIC` snapshot. The owner can make it private immediately; public reads thereafter return 404. Serve public chapter and asset responses with no-store caching to avoid a stale authorization window. Explain that material previously downloaded or copied by a visitor cannot be recalled. Public books remain readable even if the original conversion job is later deleted, because the shelf owns its own copy; deleting a shelf book is a separate confirmation and removes its data/progress. In Phase 8, a snapshot does **not** silently change when its source conversion is edited; replacing content requires creating a new shelf book. This preserves readers' existing completion history and avoids changing a public text without an explicit publish decision.
5. **Visual reader.** Separate shelf landing pages and a focused reading view with clear book/chapter typography, graceful cover design (no AI-generated cover or external image service), chapter table of contents, previous/next chapter navigation, responsive reading width, accessible contrast, keyboard focus/landmarks, font-size and light/dark preferences, loading/error states and a chapter-count progress indicator. Render GFM tables, fenced code, sanitized Mermaid and local raster images using the existing safe renderer patterns. The public reader needs only public shelf endpoints—not private `/jobs` routes. Public book URLs can be shared/deep-linked without login. Do not imply imported Markdown has PDF source pages.
6. **Progress.** For an authenticated reader, opening a chapter records its identity and timestamp (not an unreliable scroll position); completion requires an explicit Mark complete/Mark not complete control. Continue Reading chooses the last-opened chapter unless it is complete, then the next incomplete chapter in order; once all are complete it shows Completed and offers Read again. The owner of a private shelf book can track progress, and every signed-in user can independently track a public book. Guest reading uses no server-side progress, cookie-based identity or local-storage history. Unpublishing hides a public book from other readers while retaining their private progress records until it is republished; deletion erases them. Users can clear their own progress. No global completion counts or reader identities are exposed to book owners or the public.

## Architecture and API boundaries

- New migration following Phase 7 revision `76b8e4d18f01`. `shelf_books` holds opaque ID, owner, source kind (`CONVERSION_SNAPSHOT` or `MARKDOWN_IMPORT`), bounded metadata, visibility (`PRIVATE`/`PUBLIC`), storage backend, status and timestamps. `shelf_chapters` has stable ordered chapter IDs and private Markdown object/path pointers; `shelf_assets` has validated names/types/paths. `reading_positions` has a unique `(user_id, shelf_book_id)` key and last-opened chapter; `chapter_completions` has unique `(user_id, shelf_chapter_id)` and completion timestamp. Foreign keys cascade on shelf/book deletion; users cannot write another user's rows. Do not store whole books in PostgreSQL.
- Dedicated snapshot/import, shelf repository, public-read and progress services with local/MinIO storage adapters. Copy content into a shelf-owned namespace rather than pointing public routes at mutable private conversion paths. Stage/validate into a private temporary namespace, then publish metadata/pointers atomically; on failure clean staged files and keep the prior book/job downloadable. Never expose incomplete imports or partially copied chapters. Use immutable object keys for published content and bounded reads. Public visibility toggles are SQL transactions with owner locks.
- Example endpoints (exact naming can be finalized at implementation): `GET /api/v1/shelves/public`, `GET /api/v1/shelves/public/{book_id}`, `GET /api/v1/shelves/public/{book_id}/chapters/{chapter_id}`, and a restricted asset endpoint need **no session** and filter `PUBLIC` in SQL. `GET /api/v1/shelves/mine`, `POST /api/v1/shelves/from-job/{job_id}`, `POST /api/v1/shelves/import`, `PATCH /api/v1/shelves/{book_id}/visibility`, metadata edits and deletion require the owner, approved session, CSRF on changes and rate limits. Private book/chapter/asset reads use a separate owner-only path; never reuse unauthenticated routes for private content. `GET/PUT/DELETE /api/v1/reading/{book_id}` handle current user's own progress and apply SQL-side book visibility/ownership. A signed-in reader of a public book uses the same safe public content endpoints plus authenticated progress calls.
- Public responses include only approved book metadata and rendered content/asset references. Strip private paths, source job references, original filename if not intentionally chosen as the title, and owner email/username. Validate Markdown links/asset MIME types; React never executes raw HTML, external images, scripts or arbitrary Mermaid SVG. Keep the existing restrictive CSP and `nosniff`; no external fonts, CDN, tracking pixels or AI. Bound list pagination and chapter/asset transfer sizes; public read rate controls should protect infrastructure without requiring login. Log IDs, status codes and counts, not book content or reader progress details.

## Test and rollout plan

- Back up PostgreSQL and `uploads`/`outputs`/optional MinIO volumes; migrate in the existing one-command Compose stack. No new container is required. Existing jobs and Phase 7 indexes stay unchanged; **no automatic publication/backfill** of existing books.
- Unit tests: ZIP parser traversal/bomb/duplicate/type/encoding limits, Markdown/asset link validation, ordered chapters, snapshot invariance, resume algorithm, all-complete/reset cases.
- Integration tests: converted local and mocked-MinIO snapshots (including revised chapters/images), imported single Markdown and multi-chapter ZIP, atomic failure cleanup, source-job deletion vs shelf retention, public/private transitions and immediate revocation, owner isolation/admin limits, unauthenticated public reads, guest writes denied, signed-in per-user progress isolation, CSRF/rate limits, and deletion cascade.
- Frontend tests: public guest reader/deep link, private sign-in, import/publish confirmation, responsive accessible reader, complete/uncomplete/continue behavior, two signed-in users' independent progress, unsafe Markdown/asset rejection. Run Ruff, mypy, pytest, typecheck, Vitest, build and npm audit. Live Docker/PostgreSQL/MinIO and guest-access smoke testing must happen on the Docker host (unavailable in the authoring workspace).

## Explicit limitations / later options

No exact in-chapter resume position, reading-time telemetry, arbitrary named/curated collections, social comments/ratings, bookmarks/notes, offline downloads, EPUB export, PDF page mapping for imported Markdown, public full-text search or moderation workflow in Phase 8. These can be considered later. Public publishing is immediate and the owner is responsible for having rights to share the content; display a publication warning. A private book is never inadvertently made public by a job migration, import or conversion.

## Approval

The owner approved the defaults, including both conversion snapshots and Markdown uploads, chapter-level resume, and separate progress for signed-in public readers.
